# GenUI — Implementation Plan

> **For agentic workers:** execute with superpowers:executing-plans, inline. Never spawn subagents. Steps use checkbox
> (`- [ ]`) syntax for tracking. Phase 0 is a gate: do not start Phase 1 until its findings are written into the spec.
> **Revised 2026-11-04:** OpenUI Lang (native Dart + Python implementations) replaces A2UI and the `genui` package.

**Goal:** Hermes replies in Iris with native, personal UI — displays and reply kits designed from the person's own
work — written by the agent in OpenUI Lang, validated by the `hermes-iris` plugin, rendered by a pure-Dart OpenUI
implementation with Iris's own widgets, and only in Iris.

**Architecture:** `packages/openui_lang/` (pure Dart: lexer, streaming parser, evaluator, store, validator, prompt
generator, passes the OpenUI 1.0 conformance fixtures) · `lib/features/genui/render/` (Iris component library = single
source of truth, exports a LibrarySpec; widgets) · `lib/data/genui/` (REST + parsing) · `server/hermes-iris/` (Hermes
plugin: Python port of parser/validator/prompt, tools, hooks, routes, skill, store).

**Spec:** `docs/superpowers/specs/2026-10-31-genui-design.md` (decisions D1–D10, library, security, risks).

**Tech Stack:** Flutter 3.41.6 / Dart 3.11, Riverpod 3 (hand-written providers). **No new Flutter dependency** (`genui`
and `json_schema_builder` dropped; `packages/openui_lang` is a path dependency). Server: Python ≥ 3.11, FastAPI,
pytest.

## Global Constraints

- Branch `feat/genui`; each phase may branch off as `feat/genui-pN` and merge back.
- Commits under the user's name only: no `Co-Authored-By`, no `Claude-Session` line. Add files by name; never
  `git add -A`; never commit `android/gradle.properties` or `store/screenshots/`.
- Every Dart task ends with `dart analyze`/`flutter analyze` → `No issues found!` and its tests green; the last task of a
  phase runs the full `flutter test` (excluding `--tags live`) and `dart test` in `packages/openui_lang`. Every server
  task ends with `pytest server/hermes-iris` green.
- **Fixtures are the contract.** Vendored OpenUI fixtures (pinned commit, licence + attribution checked first) are run
  by both Dart and Python. A skipped fixture needs a one-line reason in `FIXTURES_SKIPPED.md`.
- Live tests against hermes.shreyaskamat.in wait ≥ 240 s per turn and re-flag the session after reconnect.
- Every plugin route takes `?profile=`; every Iris call goes through `DashboardChat._scoped`-style scoping.
- Nothing personal is injected into a turn before the person approves it in Iris.
- Never log programs, `data`, action contexts or study samples unredacted (`IrisLog.redact`).
- Copy is British English, matches `docs/design-language.md`; no raw error codes in a primary line.

## Phase 1 — `packages/openui_lang` (Dart)

Pure Dart, no Flutter imports, own `pubspec.yaml`, `dart test`.

- [x] **1.1 Skeleton + fixtures.** Package, vendored `test/fixtures/` (pinned commit, `NOTICE`), a fixture runner that
  discovers cases and reports each as its own test (all red at first).
- [x] **1.2 Lexer.** Identifiers (`Upper` component, `lower` ref, `$state`, `@builtin`), strings with escapes,
  numbers (negation rule), `true/false/null`, `//` and `#` comments, never throws. Tests + fixtures.
- [x] **1.3 Parser.** Statements (`name = expr`, multi-line inside brackets/strings/ternary), expressions by EBNF §1.6,
  calls with positional args and optional commas, arrays/objects, member access/indexing, hoisting, `root` entry rules,
  last-wins duplicates, orphans. `LibrarySpec`/`ComponentSpec` models with JSON round trip; positional → named props.
- [x] **1.4 Validation + errors.** All error codes from `language.md`, structured `OpenUIError` with `hint` signatures;
  "smallest unit removed, rest renders". Tests per code.
- [x] **1.5 Streaming parser.** `set(fullText)` → `ParseResult{root, meta{incomplete, unresolved, statementCount,
  validationErrors}}`; implicit closing of strings/brackets; completed statements are never overwritten by pending
  ones; prefix cache with re-parse fallback; final result equals batch parse (property-style test over fixture
  prefixes at every character boundary).
- [x] **1.6 Evaluator + store.** Operators/precedence, member pluck, `.length`, builtins (`@Count @First @Last @Sum @Avg
  @Min @Max @Filter @Sort @Round @Abs @Floor @Ceil @Each`), custom functions registry, `$state` defaults, two-way
  bindings, re-parse never clobbers user-changed values, iteration/depth caps, cycle detection.
- [x] **1.7 Prompt generator.** `generateSystemPrompt(library, options)` byte-deterministic; golden snapshot test.
  Options for v1: `bindings`, `builtinFunctions`, custom `actions`/`functions`, `preamble`, `examples`,
  `additionalRules`; no tool calls, no edit/inline mode.
- [x] **1.8 Phase check.** `dart test` green (conformance report: N passed / M skipped with reasons), `dart analyze`
  clean, a README with usage, no `dart:ui` anywhere.

## Phase 2 — `hermes-iris` server package

- [x] **2.1 Skeleton.** `server/hermes-iris/{plugin.yaml,__init__.py,dashboard/manifest.json,dashboard/plugin_api.py}`,
  `pyproject.toml`, README with install/enable/upgrade. `GET capabilities` → `{version, openui:"1.0", library_ids,
  features}`. TestClient route test.
- [x] **2.2 Auth.** Per Phase 0.2. Test: unauthenticated → 401.
- [x] **2.3 Store.** `genui/store.py` per-profile dir `~/.hermes/iris/<profile>/` (`profile.json`, `templates/`,
  `surfaces/<session>/<surface>.json`, `usage.jsonl` rotated at 1 MB); atomic writes; path components
  `^[A-Za-z0-9_-]{1,64}$`. Tests incl. traversal.
- [x] **2.4 Python OpenUI port.** `openui/{lexer,parser,validate}.py` (no evaluator; validation only), fed by
  `catalog/v1.library.json`. Runs the same vendored fixtures (parse/validate categories; skip reasons recorded).
  Limits from the spec (statements, bytes, depth, strings). Errors rendered as short model-readable lines with the
  component signature hint.
- [x] **2.5 Python prompt generator.** `openui/prompt.py` byte-identical to the Dart one for the same LibrarySpec; the
  golden snapshot from 1.7 is the shared test. Until Phase 3.1 produces the real library, use a 10-component sample.
- [x] **2.6 Session flag.** `POST sessions/{id}/genui`, keyed per Phase 0.5, persisted for restarts. Tests.
- [x] **2.7 `iris_ui` tool.** Args per spec; `template`+`data` expansion in `genui/templates.py` (data checked against
  the template's JSON Schema, then `data = {…}` prepended); parse + validate; store; return `{ok, surface_id, rev}` or
  `{ok:false, errors}`. `fallback` required. Tests: update (rev++), delete, expansion, rejection messages.
- [x] **2.8 Guards.** `pre_tool_call` blocks `iris_*` in unflagged sessions; `transform_tool_result` trims the receipt.
- [x] **2.9 Turn context.** `genui/context.py` ≤ 2,500 chars (rules, component digest, approved-template index);
  `pre_llm_call` only for flagged sessions. Snapshot + budget tests.
- [x] **2.10 Surface routes.** `GET surfaces/{session}[/{surface}]`. Tests.
- [x] **2.11 Skill `iris-genui`.** `SKILL.md` (render vs plain text, text-complete rule, one surface per idea, prefer
  templates, reply kits for decisions, update rather than recreate, no secrets in data, write OpenUI Lang with `root`
  first), `references/library.md` (generated by the Python prompt generator from the library JSON, regenerated by a
  script and checked by a test), `references/patterns.md` (8–10 worked programs). `ctx.register_skill`.
- [ ] **2.12 Live check.** Install, flag a session with `curl`, ask for "a status card for my cron jobs", confirm a
  stored valid program and a text reply; record first-try validity and retries over 10 varied prompts.

## Phase 3 — Rendering surfaces in Iris

- [x] **3.1 Iris library, part 1.** `render/iris_library.dart`: `IrisComponent` definitions (ordered typed props,
  descriptions written to say what the type doesn't, per `prompt.md`) for layout + text & data components and the
  custom functions; `toLibrarySpec()`. A test exports `server/hermes-iris/catalog/v1.library.json` and fails on drift;
  re-generate the server skill reference and re-run Phase 2 tests.
- [x] **3.2 Node builder.** `render/node_builder.dart`: `ElementNode` → widgets on `lib/design` tokens; incomplete or
  unresolved nodes → skeleton placeholders; errors → "can't show this" chip; per-component semantics labels.
- [x] **3.3 `OpenUiView`.** Owns a `StreamingParser` + `Store`; takes the program text (whole, or a growing string if
  D2b ships); loading shimmer; fallback text on fatal error; max height with "Show all". Goldens light/dark for every
  component (follow the existing goldens setup).
- [x] **3.4 Capability + API.** `ServerCapability.irisGenui('/api/plugins/iris/capabilities', 'Generative UI')`;
  `lib/data/genui/{genui_models,genui_api,genui_parser}.dart` (`iris_ui` tool event → `UiSurfaceRef`; `<iris-action>`
  strip/parse). Unit tests with recorded Phase 0 payloads.
- [x] **3.5 Transcript integration.** `UiSurface` item; `ChatController` maps `iris_ui` events and stored history rows
  to it (fetching the program by id if args are partial); rendered inside the assistant block. Hide hook context if
  Phase 0.4 found it stored. Fake-backend tests.
- [x] **3.6 Session flagging + settings.** `GenUiController` flags sessions on open/create/resume/reconnect when enabled
  and the capability exists; per server+profile toggle in `PreferencesStore`, off by default; settings section shows
  plugin status and install help.
- [ ] **3.7 Phase check.** Full tests, analyze, debug APK; live: ask for a status card, see it render on the emulator
  (wait ≥ 240 s; emulator storage gotchas).

## Phase 4 — Actions, inputs and reply kits

- [x] **4.1 Library part 2.** `Tabs`/`Tab`, `Expander` (local `$state`), charts (`Sparkline`, `LineChart`, `BarChart`,
  `Donut` as painters), `Diff`. Goldens.
- [x] **4.2 Inputs.** `Button`, `ChoiceChips`, `Input`, `Slider`, `Toggle`, `DatePicker`, `Stepper`, `ApproveReject`,
  `Submit`, bound to `$vars` via the store; platform-adaptive via `lib/design/platform`. Tests: typing updates a
  dependent expression; re-parse (update of the surface) doesn't clobber user input.
- [x] **4.3 `@Ask` action → message.** Builds the visible sentence plus `<iris-action>{…}</iris-action>`; goes through
  `ChatController` (busy mode, queue). Transcript hides the block. Skill documents how to read it. Tests.
- [x] **4.4 Reply kits.** `placement: "reply_kit"` docks above the composer (`reply_kit.dart`), dismissible, replaced by
  the next kit, cleared when the person types. Tests + goldens.
- [x] **4.5 Surface updates.** `iris_ui` on an existing id updates in place (rev); older revs in history show the
  latest with an "updated" tag.
- [x] **4.6 Live check** of an approve/hold reply kit end to end.
